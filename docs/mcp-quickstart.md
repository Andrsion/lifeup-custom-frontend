# LifeUp MCP 安装与使用指南

> 本文帮助你将支持 MCP 的 AI 客户端连接到手机上的云人升。客户端界面和官方步骤如有变化，以[官方 MCP & Skills 文档](https://wiki.lifeupapp.fun/zh-cn/guide/api_mcp.md)为准。

## 1. MCP 是什么？

LifeUp MCP 让 AI 客户端通过局域网连接云人升，读取人升数据，并在你的明确指令下调用人升功能。

- **只想让 AI 操作人升**：按本文安装，不必先开发网页。
- **想制作网页、桌面看板或机器人**：参阅[项目实现方案](custom-ui-ai-mcp.md)。
- MCP 不会天然知道你的主题、清单名或自定义货币；应以真实读取的数据或你明确提供的信息为准。

## 2. 安装前准备

- [ ] 手机已安装并能正常打开《人升》。
- [ ] 已安装并启动《云人升》，默认端口为 `13276`。
- [ ] 在人升中按官方说明开启 MCP，并向云人升授权“读取人升数据”。
- [ ] 手机与电脑位于同一局域网，且路由器没有阻止设备互访。
- [ ] 电脑安装 Node.js 20+；终端执行 `node -v`、`npx -v` 能显示版本号。
- [ ] 已安装支持 MCP 的桌面 AI 客户端。

**版本要求：** 官方 Wiki 的 MCP 页面写明人升 1.106.0+、云人升 3.0.0+。当前 SDK 的 `lifeup-cloud` Skill 对完整工作流要求更具体，见[当前 Skill 文档](https://github.com/Ayagikei/LifeUp-SDK/tree/main/mcp/skills/lifeup-cloud)，其中要求云人升 3.0.1+。不要将 MCP / Skills 的版本门槛当成所有 Cloud HTTP 路由的统一要求。

## 3. 安装 MCP Server

官方 npm 包是 `@lifeup/mcp`。在客户端的 MCP 配置中新增名为 `lifeup` 的服务器：

```json
{
  "mcpServers": {
    "lifeup": {
      "command": "npx",
      "args": ["-y", "@lifeup/mcp"]
    }
  }
}
```

保存后，按客户端要求重新加载配置或重启客户端。不要覆盖整个客户端配置文件；将 `lifeup` 项合并到现有的 `mcpServers` 即可。

### 自动发现失败时，指定设备地址

默认会尝试通过 mDNS 发现云人升。如果发现失败，可显式设置 `LIFEUP_HOST`，地址使用云人升实际显示的主机和端口：

```json
{
  "mcpServers": {
    "lifeup": {
      "command": "npx",
      "args": ["-y", "@lifeup/mcp"],
      "env": {
        "LIFEUP_HOST": "192.168.1.8:13276"
      }
    }
  }
}
```

请将示例 IP 替换为自己手机的实际地址。

### 云人升启用了 Token 时

仅当云人升确实配置了 Token 时，才添加 `LIFEUP_TOKEN`。官方文档要求使用**原始 Token，不加 `Bearer ` 前缀**。不要将 Token 提交到仓库、贴到公开聊天、截图或写入前端代码。

```json
"env": {
  "LIFEUP_HOST": "192.168.1.8:13276",
  "LIFEUP_TOKEN": "替换成你自己的Token"
}
```

npm 源访问不稳定时，可按客户端命令参数格式在 `args` 中加入 `--registry=https://registry.npmmirror.com`。若 macOS 图形客户端找不到 `npx`，可将 `command` 改为本机 `npx` 的绝对路径。

## 4. 首次连接验证

保存配置后，按客户端的方式启用或信任新服务器，然后新开一个对话，依次提问：

1. “列出 LifeUp MCP 当前可用的工具。”
2. “检查连接状态和人升、云人升版本。”
3. “只读取我的任务列表和属性，暂时不要修改任何数据。”

工具列表可见不等于连接已成功。只有只读查询实际返回了你人升里的数据，才算完成首次连通验证。

官方 MCP 的常见工作流是：

1. `discover`：通过 mDNS 发现设备。
2. `connect`：需要时指定云人升地址。
3. `status`：检查连接和版本。
4. `list_data`：读取任务、商品、属性等数据。
5. `call_api`：调用具体 API 方法；执行前先通过官方 Skill 的 `help` 查看参数。

不同客户端对工具的呈现方式不同。若找不到上述工具名，让 AI 列出实际可用的 LifeUp 工具，不要假设每个客户端界面相同。

## 5. 安装后怎么用？

连接成功后，可以直接用自然语言描述目标。以下是提问范例；涉及写入的任务应先确认对象和执行计划。

### 查询与规划

- “列出今天还没完成的任务，按优先级整理，并建议先做哪几项。”
- “读取我的属性等级，指出当前等级较低的属性。”
- “总结本周番茄、金币和经验的变化；如果数据无法读取，请明确说明。”

### 数据分析

- “统计本月金币流水，说明主要来源，并列出金额最大的几笔。”
- “回顾我今天完成的任务，帮我整理成一段日报。”

### 创建与修改

- “帮我设计一组提升专注力的日常任务，先给出任务和奖励方案，等我确认后再创建。”
- “把任务 X 标记为完成。执行前先确认匹配到的是哪一个任务，完成后核对结果。”

建议先从只读查询开始。确认数据、连接和字段无误后，再尝试写操作。

## 6. 安全边界

- **先读后写**：先读取实际数据并确认目标对象，避免操作到名称相似的任务。
- **写操作要明确**：完成任务、购买、奖励、删除或批量修改前，应明确目标；影响较大的操作先展示计划并等待确认。
- **超时不要盲目重试**：先重新读取相关数据，核实操作是否已生效，不能直接重复提交。
- **删除操作**：按官方工具要求提供确认参数；不要把示例中的清理指令当成默认操作。
- **保护 Token**：不要将 Token 放进公开仓库、URL、前端代码、日志或截图。
- **核对业务结果**：重要操作后在 MCP 返回结果或人升 App 中检查实际状态。工具不可用或结果不明确时，不要声称成功。

## 7. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| MCP 服务器启动失败 | 检查 Node.js 20+、`npx` 是否可用；图形客户端找不到命令时使用绝对路径。 |
| 找不到云人升 | 确认云人升已启动、手机和电脑在同一局域网；检查 AP 隔离；必要时设置 `LIFEUP_HOST`。 |
| 连接超时 | 核对实际 IP、端口和局域网访问；手机休眠后先重新检查状态。 |
| Token 认证失败 | 仅在云人升启用了 Token 时排查；核对 Token 是否正确，且没有添加 `Bearer ` 前缀。 |
| 已连接但读不到数据 | 确认人升正在运行，并已向云人升授权读取数据；检查工具返回的实际错误。 |
| 部分工具或字段不可用 | 核对人升、云人升版本，并以对应的官方 MCP、Skills 与 Cloud HTTP 文档为准。 |
