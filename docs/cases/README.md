# 社区界面案例

这里收录社区投稿的界面：一套换名、一份可运行示例、或一篇完整施工稿。

## 怎么投稿

**手机直接投稿（推荐，不需要 Git 或电脑）：** 打开[完整界面案例投稿表单](https://github.com/Andrsion/lifeup-custom-frontend/issues/new?template=full-case-submission.yml)，填写案例说明，上传 ZIP 或粘贴单页 HTML，还可附截图。提交后 GitHub Actions 会自动进行静态脱敏检查并回帖；检查器不会执行投稿代码，检查通过也不等于正式收录。

ZIP 附件最大 25 MB。请勿包含真实 Token、手机 IP、个人数据、真实 config.json、备份文件或 node_modules。多文件项目建议把 HTML、CSS、JS 和必要的示例配置打包成 ZIP。

**传统方式（适合会用 Git 的投稿者）：**

**第 0 步：脱敏。** 运行检查器，确认没有 ✖：

```bash
python3 scripts/case_check.py <你的 html 文件或目录>
```

常见 ✖：文件里夹带自己的 token、真实手机 IP（`192.168.*` / `10.*`）、手机号、大段 base64、`config.json`、`.lfbak` 备份。⚠ 级提示（外部 CDN、外链图片）请在投稿说明里解释一句即可。

**第 1 步：生成骨架。**

```bash
python3 scripts/case_check.py <路径> --emit --slug <小写英文短名>
```

例如 `--slug adventurer-board`（只允许小写字母、数字、连字符）。会在 `docs/cases/_drafts/<slug>.md` 生成骨架，配色、换名、分区会自动填好，**留三处等你写**：为什么好玩 / 灵感来源 / 机制决定情绪（紧迫·松弛·期待）。

**第 2 步：提交。** 传统方式二选一：
- 提 Issue「主题 / 换名 投稿」：适合只投主题设定，不交完整代码；
- 提 PR：把 `_drafts/` 里的文件移到 `docs/cases/`，在本页「已收录」补一行，再提交。

如果不想碰 Git，使用本页开头的完整界面案例投稿表单，或在频道 / 群发帖带截图并注明「可投稿」，由维护者代为整理。

## 用 AI Agent 准备投稿（Vibecoding）

Vibecoding（氛围编程）是通过自然语言描述需求，让 AI 帮你生成或修改代码。如果你的界面是这样做出来的，可以把 [AI 投稿提示词](_agent-prompt.md) 全文复制给能够读取项目文件、编辑文件并运行命令的 Agent，让它按规范整理材料、运行检查并生成草稿。

> 提示词文件开头带有用途注释，属于辅助工作流，不是正式案例。Agent 检查通过不等于审核通过；不得自动提交或收录，仍需按下方流程由维护者审核。

## 投稿要求

- **必须脱敏**：不得包含 token、真实内网 IP、手机号、个人数据或 `.lfbak` 备份。
- **注明授权**：默认视为同意以本仓库许可（见 [LICENSE](../../LICENSE)）收录；不愿授权请提前说明。
- **说明数据来源**：真实云人升数据 / 静态假数据 / 纯设计稿，三者区别要在开头写清，免得别人照着跑不通。
- **截图可选**，但有图明显更容易被收录与转发。

## 维护者导入投稿

审核 Issue 的内容、授权、素材版权与自动检查结果后，打开 **Actions → import-case → Run workflow**。先用 `dry_run = true` 预览；确认没有 RED 后再用 `dry_run = false` 正式导入。工作流只在手动触发时拥有仓库写权限，不会执行投稿代码。导入后仍需人工补齐「为什么好玩 / 灵感来源 / 机制决定情绪」。

收录进本目录并在 [世界观 / 主题参考](../samples.md) 加一行索引，CHANGELOG 记一条，署名保留作者。
