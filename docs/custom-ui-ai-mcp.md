# 自定义人升：用云人升把 App 变成可被调用的服务（自定义界面 + AI + MCP 实现方案）

> **这是什么**：一份开箱即用的实现方案 —— 在《人升》(LifeUp) 之上做一层「自定义界面」（网页 / 桌面 / 机器人），并接入 AI。所有数据与规则都在**手机端人升 App** 里跑，网页只做「展示 + 转发」。
>
> **给谁看**：想自己搭人升看板、或用 AI（MCP）直接操作人升的玩家。**不需要会写代码** —— 把本文整篇喂给 AI 工具 / Agent 即可。

## 🚀 一、快速上手（多数人只看这里）

### 1｜先懂一句话原理

你要做的是**人升之上的一层「自定义界面」**——所有数据、规则、计算（任务实例、gid、惩罚、金币、开箱）全在**手机端人升 App** 里跑；这层界面只做三件事：**展示 → 收集操作 → 转发给云人升**。

| 能力 | 作用 | 入口 |
| --- | --- | --- |
| **读** | 取任务 / 商店 / 仓库 / 合成 / 成就 / 金币 / 统计 | 云人升 Query：`GET /tasks`、`/items`、`/synthesis`… |
| **写** | 完成、放弃、购买、使用、合成、领奖、建任务 | `POST /api/contentprovider`（有返回值）/ `POST /api`（launch，无返回值） |
| **智能** | 自然语言 → 自动调接口 | LLM + function calling，或官方 **MCP** 免开发接入 |

> 🎨 **它的名字和皮肤，跟着你的玩法体系走。** 别叫「面板」这种通用词——动森体系可以叫「**无人岛生活台**」，修仙体系可以叫「宗门榜 / 洞天福地」，赛博朋克就用你自己的代号……**皮肤、配色、命名全部随体系自定义**，别让名字和世界观割裂。

**一句话：门槛很低，不用为它买高配电脑——甚至不一定非要买电脑。**

## 🧩 二、原理与接口（想搞懂 / 二次开发再看）

### 定位：人升之上的一层「自定义界面」

**网页本身不存储业务数据、也不重写人升的核心逻辑**；所有数据、规则、计算（任务实例生成、gid、惩罚、金币、开箱）全部在**手机端人升 App** 里跑。云人升是手机上的 HTTP 服务，这层界面通过调用它的接口，**远程操控手机里的人升**。

**这层界面只做三件事**：UI 展示 → 收集用户操作 → 转发请求给云人升 → 把返回结果渲染出来。

* ✅ 不用自建业务库（不需要 SQLite）
* ✅ 不用自己实现周期 / 连胜 / 惩罚 / 金币算法

### 架构

```
自己做的前端（Web / 桌面 / 小程序 / 语音 / 机器人）
↕ HTTP
本地代理层（推荐：解决 CORS + 隐藏 Token + 做缓存）
↕ HTTP :13276（局域网，mDNS _lifeup._tcp 可发现）
云人升（手机端）
↕ ContentProvider
人升 App（1.106+，需开启「读取人升数据」）
```

* **网页前端**：一个纯前端项目（用什么框架，交给 AI 挑最省事的即可）
* **所有能力**：全部走云人升 HTTP API
* **⚠️ 网页绝不自己实现任何规则**：任务周期、逾期惩罚、连胜统计、经验 / 金币奖励、gid 生成……一律由 API 返回，网页只负责展示与触发
* **中间为何要加一层薄代理**：浏览器直连云人升会被 CORS 拦，且 Token 会暴露——加一层薄代理是最稳的做法（开发阶段 Vite 的 `server.proxy` 就兼任这一层）

### 读：Query 层（GET）

* 资源清单：`tasks` / `task_categories` / `items` / `item_categories` / `skills` / `achievements` / `synthesis` / `history` / `coin` / `info` / `statistics` / `level_defines` / `pomodoro_records` / `coin_records` / `inventory_records` / `exp_records` / `step_records`
* 取数规则：默认 **compact 行 + limit=20 + offset 分页**（看 `hasMore`）；**只在要修改的那几行**加 `detail=true`，不要全量 detail
* 关键字段：
  * 任务 `status`：0 未完成 / 1 完成 / 2 逾期 / 3 放弃
  * 成就 `status`：**1 = 已完成可领奖**（0 未完成、2 已领）
  * 任务 `frequency`：0 单次 / 1 每日 / N>1 每 N 天 / -1 无限 / -3 艾宾浩斯 / -4 每月 / -5 每年
  * **`id` 每个重复周期都会变，`gid` 不变**——缓存与跨周期操作用 gid

### 写：Action 层（POST）

* 默认 `POST /api/contentprovider`，body `{ "url": "lifeup://api/..." }`，**返回结果**
* 需要 UI（页面跳转 / 确认弹窗 / 番茄钟启动）才用 `POST /api`（launch，只保证送达、拿不到返回值）
* 常用方法：`complete` / `give_up` / `purchase_item` / `use_item` / `synthesize` / `add_task` / `reward` / `loot_box`
* 批量：`call_api_batch`（≤20 个方法，顺序保持；批内后续调用看不到前面结果）
* ⚠️ **写操作不幂等**（complete / skip / reward）：超时**不要自动重试**
* 检查返回：`HTTP 200 + code=200` 只代表送达，必须再看 `ok` 与 `data`

### AI：两条接法

**A. 自建 function calling（能融进自己的界面）**

* 把「读接口 + 写接口」封装成 tools，交给 LLM（如 DeepSeek）
* LLM 理解意图 → 选工具 → 填参 → 回填结果 → 生成自然语言回答
* 适合：自定义界面内的 AI 助手、QQ / 微信机器人、语音助手

**最小实现（三件套）**

| 层 | 做什么 | 用到 |
| --- | --- | --- |
| 数据层 | 拉数据渲染成卡片（任务 / 商店 / 仓库） | `GET /tasks`、`/items`、`/coin` |
| 交互层 | 按钮触发完成 / 购买 / 合成 | `POST /api/contentprovider` |
| AI 层 | 输入框 → LLM → 调 tools → 回显结果 | LLM API + function calling |

* **形态怎么选**：最省 = 单文件 HTML + JS；要组件化 = React / Vue；桌面端 = Tauri / Electron；不想做界面 = 直接接 QQ / 微信机器人
* **必须有中间件**：本地代理层（解决浏览器 CORS + 藏 Token）
* **刷新策略**：定时轮询（如 30 秒）或监听云人升广播事件
* **体验兜底**：把 `10001`（人升未运行 / 未授权）、`401`（Token 错误）翻译成用户看得懂的提示，而不是显示错误码

**B. 官方 MCP（零代码接入现成 AI 客户端）**

* 人升「设置 → 实验」开启 MCP；客户端（WorkBuddy / Cursor / Claude Desktop / Claude Code / Codex 等，或任意 MCP 客户端）配置后即可用。**各客户端的手把手接入见「客户端接入 MCP」。**
* 适合：只要「让 AI 直接管理人升」，不需要自制 UI

### 实现步骤

1. **手机侧达标**：人升 v1.106.0 与 云人升 3.0.0+；云人升开启「读取人升数据」；记下 `IP:13276`
2. **连通自测**：请求 `GET /info`，返回应用 / 云版本即通
3. **本地代理**：Node / Python 写薄层，转发 Query 与 Action（若云人升设了 Token，用 **raw token 头**，不是 Bearer）
4. **连接配置页**：输入地址 + Token，调 `GET /info` 测连通，可扫码
5. **角色面板 / 资源栏**：`GET /coin`、`/skills` 渲染金币与属性
6. **任务列表**：读 `/tasks` + `/task_categories` 渲染卡片；「完成 / 放弃」调 `complete` / `give_up`；再做新建任务（单次 / 循环）
7. **仓库 + 宝箱（开箱）**：`use_item` / `loot_box`；**商店兑换**：`purchase_item`；**合成**：`synthesize`
8. **AI 助手**：接 LLM + tools（读 + 写），system prompt 里交代人升语义（任务 / 金币 / 里数 / 成就）
9. **实时刷新（可选）**：定时轮询 Query，或监听云人升广播事件
10. **模板导入导出 / 日历视图（可选）**：展示 API 返回的历史

## 📚 三、参考手册（按需查）

### 坑与限制

**⚠️ 三个关键前提（先确认）**

1. **手机侧先达标**：人升 v1.106.0 ＋ 云人升 3.0.0+，并开启「读取人升数据」。
2. **同一局域网**：手机与电脑在同一 Wi-Fi（路由器开了 AP 隔离也会失败）。
3. **跨域（CORS）**：浏览器直连云人升会被拦、Token 也会暴露 → **必须加一层薄代理**。
   * 开发阶段：用 **Vite 的 `server.proxy`** 代理转发（`vite dev` 同时充当本地代理）；
   * 脱离 dev server 用静态页直接打开：**必须另配一层薄代理**。

**常见坑**

| 现象 | 原因 / 处理 |
| --- | --- |
| `code 10001` | 人升没运行，或云人升未获「读取数据」授权 |
| `HTTP 401` | 云人升设了 Token，需带 **raw token 头** |
| 找不到实例 | 不在同一 Wi-Fi / 路由器开了 AP 隔离 → 手动填 IP:端口 |
| 手机休眠后超时（10s） | 重连一次即可，**不要死循环 discover** |
| 写操作重复执行 | 不幂等，超时**别重试** |
| 缓存错乱 | 用 `gid` 而非会变的 `id` |
| 版本不够 | 需人升 v1.106.0 正式 + 云人升 3.0.0+ |

**两条铁律**

* **网页禁止自算规则**：连胜、逾期扣血、经验金币、gid 生成，全由云人升 API 返回。
* **接口名 / 参数 / 返回结构一律以官方为准**：https://wiki.lifeupapp.fun/zh-cn/guide/api_cloud.md （与 web 冲突时以 web 为准）。

> 📎 **「组件清单：照搭一个自己的看板」与「可以做成什么」——见文末「附录：组件清单 & 灵感库」。**

### 权威信息源（AI 默认该读什么）

> **默认路径 = ① 官方 MCP 自带知识 ＋ ② 公开 web 文档**。这两样**任何用户都拿得到**：装了 MCP 就有 `help`；文档在公网、免登录。
>
> ⚠️ **不要假设 AI「天生知道」** —— 你的玩法体系、清单名、货币名只存在于你自己的 App 里；要么让它先读真实数据（MCP），要么明确告诉它，**别默认它知道**，否则它会在版本号 / 参数 / 步骤上**直接瞎猜**。

| 用途 | 权威源 |
| --- | --- |
| 云人升 HTTP 接口 | https://wiki.lifeupapp.fun/zh-cn/guide/api_cloud.md |
| MCP & Skills | https://wiki.lifeupapp.fun/zh-cn/guide/api_mcp.md |

### 客户端接入 MCP

> **默认推荐 WorkBuddy**：门槛最低 —— 装好客户端、配一次 MCP，就能用人话操作人升。进阶玩家再用 dsh。

**A.（默认推荐）WorkBuddy · 全图形界面**

**① 下载安装**

* 到 WorkBuddy 官网下载**桌面端**（Windows / macOS / Linux），安装后登录（扫码 / 账号）。
* 另装 **Node.js 20+**（MCP 靠 `npx` 启动）——终端执行 `npx -v` 有版本号即 OK。

**② 配置人升 MCP（一次性）**

1. 手机侧：人升「设置 → **实验**」开启 **MCP**；人升与电脑**同一 Wi-Fi**；云人升已启动（默认端口 `13276`）。
2. WorkBuddy 左侧「**连接器**」→「**管理连接器**」→「**自定义连接器**」→「**MCP 服务管理**」→「**配置 MCP**」。
3. 粘贴下面这段（`LIFEUP_HOST` 换成云人升界面显示的地址；可留空走 mDNS 自动发现）：

```json
{
"mcpServers": {
"lifeup": {
"command": "npx",
"args": ["-y", "@lifeup/mcp"],
"env": { "LIFEUP_HOST": "192.168.1.8:13276" }
}
}
}
```

* 设了 Token 再加 `"LIFEUP_TOKEN": "你的token"`（**原始 Token，不加 Bearer**）；npm 源慢可在 `args` 加 `"--registry=https://registry.npmmirror.com"`。
* **保存** → 回连接器列表，把新增的 `lifeup` 点「**信任**」并**启用** —— **小圆点变绿**才算真连上。

**③ 验证 & 使用**

* 新开一个对话，说「**列出 lifeup 下的所有工具**」；能列出即接入成功。
* 之后说人话即可：「把今天的日常任务都完成」「看看我各属性等级，设计一批练级任务」「这个月金币都从哪来的」。

**④ 坑**

* 只往配置文件**合并**新的 `mcpServers` 条目，别整文件覆盖；
* 连接器**不点「信任」不生效**（圆点不变绿 = 没连上，常见错觉）；
* macOS 图形端常找不到 `npx` → 用 `npx` / `node` 的**绝对路径**；
* 版本不够：需人升 **v1.106.0**＋、云人升 **3.0.0**＋。


**B. 进阶：dsh（DeepSeek Harness）· 本地 Agent**

dsh 是 DeepSeek 官方开源的 Agent 运行框架（「一切皆插件」，底层 Cordis）。它**不是新模型**，而是模型外面的运行环境；**MCP 不是内置**，要装官方 MCP 插件。

1. **前置**：Node.js **^22.19 / ≥24**。
2. **起 dsh**：

```bash
npx @deepseek-ai/dsh web      # 打开 http://127.0.0.1:3080
```

3. **装 MCP 插件**：官方 `@deepseek-ai/dsh-mcp-client`，**一个插件实例 = 一个 MCP 服务器**；在 profile 配置里加一行指向人升 MCP：

```yaml
# 示意，字段以官方文档为准
- plugin: '@deepseek-ai/dsh-mcp-client'
config:
name: lifeup
command: npx
args: ['-y', '@lifeup/mcp']
```

4. **验证**：挂载后外部工具会注册成 dsh 原生工具，名字形如 `mcp__lifeup__<工具>`；在对话里说「列出 lifeup 的工具」，或直接下指令。
5. **坑**：dsh 处于 **developer preview（0.1.0-rc.x）**，官方明确**会有破坏性变更**，配置字段以官方文档为准；长期 / 生产使用请自担风险。

> 两个客户端都走同一套 Agent 流程：`discover → connect → status → list_data → call_api`（详见「AI：两条接法」）。MCP 安装细节以官方为准 → https://wiki.lifeupapp.fun/zh-cn/guide/api_mcp.md

# 附录：组件清单 & 灵感库

## 一、组件清单：照搭一个自己的看板

把界面拆成可照抄的模块——**页签名、皮肤、叫法随你的体系改**，数据源照下表对应即可。

**① 顶部状态条**

* 连接信息：地址 + 人升 / 云版本（`GET /info`）
* 资源栏：金币 / 属性（`GET /coin`、`/skills`）
* 刷新按钮 + 自动刷新开关（轮询间隔自定，如 6~30 秒）

**② 左侧页签 → 数据源**

| 页签（可改名） | 读 | 写 |
| --- | --- | --- |
| 任务 | `GET /tasks` + `/task_categories` | `complete` / `give_up` / `add_task` |
| 商店 | `GET /items` + `/item_categories` | `purchase_item` |
| 仓库 | 物品持有（见官方文档 `items` / `inventory_records`） | `use_item` / `loot_box` |
| 合成 | `GET /synthesis` | `synthesize` |
| 成长 | `GET /skills` + `/level_defines` | — |
| 统计 / 体检 | `GET /statistics`、`/history`、各类 `*_records` | — |

> 「成长」「体检」「统计」这类页面官方没有现成定义——用上面的接口自己组就行。

**③ 任务卡片字段**

* 名称 / 清单名（分类）
* 周期 `frequency`：0 单次 / 1 每日 / N 每 N 天 / -1 无限 / -3 艾宾浩斯 / -4 每月 / -5 每年
* `gid`（稳定）——做 key 和缓存**用它，不要用会变的 `id`**
* 状态 `status`：0 未完成 / 1 完成 / 2 逾期 / 3 放弃
* 奖励、期限（字段以官方文档为准）
* 按钮：完成 / 放弃

**④ 右侧 AI 助手**

* 输入框 → LLM（function calling）→ 调工具 → 回显
* **只暴露你允许的工具**（如「读 + 完成 + 开箱」）；改任务 / 改价这类可以不给，让它回去找完整 agent

**⑤ 哪些接口直出、哪些得自己来**

| 东西 | 谁做 |
| --- | --- |
| 任务 / 商品 / 仓库 / 合成 / 属性 / 金币 / 统计 | 接口直出（Query） |
| `gid`、周期、状态、奖励发放、扣血、连胜 | **App 算**，网页只展示 |
| 双货币（如「铃钱 / 里数」） | **自映射**（人升原生是单一金币；要双币得用 金币 + 属性 / 物品 组合；ulives 才是原生多货币） |
| 分组筛选、期限展示、夜间模式、主题文案 | 纯前端自己组（接口只给数据） |

## 二、可以做成什么

* **任意皮肤的看板**：动物森友会 / 赛博朋克 / 极简……（Web、桌面、平板大屏）
* **AI 外壳**：语音说「帮我把今天的日常做完」，AI 批量调 `complete`
* **社群机器人**：群友打卡 → 自动建任务 / 发奖励（结合 QQ 机器人）
* **桌面小部件 / 番茄钟联动**
* **自动化**：Tasker / MacroDroid 触发 → 调人升 API（Tasker / MacroDroid 见人升官方文档）
